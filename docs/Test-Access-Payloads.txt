  3.4  ITEM 4 - ADMIN API   -   https://api.gedaaistar.et/api/admin/v1
--------------------------------------------------------------------------------

  Authentication model - TWO STEPS
  --------------------------------
    Step 1  POST /auth/login             body: { email, password }
            Response contains a short-lived MFA challenge token
            (JOSE typ = "mfa-challenge", TTL 300 s) and either
            state = "MFA_REQUIRED" (token already enrolled) or
            state = "MFA_ENROLLMENT_REQUIRED" (first login, response
            also contains { setup.secretBase32, otpauthUri, issuer }
            for QR-code enrolment).

    Step 2  POST /auth/verify-mfa        body: { challengeToken, code }
            Response is the final { accessToken, refreshToken,
            accessTokenExpiresAt, refreshTokenExpiresAt, admin } .

  Bearer JWT for admin
  --------------------
    Algorithm       : HS256
    aud             : "admin"
    aud_type        : "ADMIN"
    Access TTL      : 15 minutes
    Refresh TTL     : 30 days (rotating)
    Roles claim     : "roles" array; possible values
                       SUPERADMIN, PRODUCT_MANAGER, ORDER_MANAGER,
                       CUSTOMER_MANAGER

  Test account
  ------------
    Same audit-admin@gedaaistar.et account as Item 3. Auditors may use
    it against the Admin API through curl.

  Sample payloads and curl commands for this API are in Section 5.

  3.12 ITEM 12 - YAGOUTPAY RETURN ENDPOINTS
--------------------------------------------------------------------------------

  URLs            : https://api.gedaaistar.et/api/storefront/v1/payment/
                    yagoutpay/return        (gateway success POST)
                    https://api.gedaaistar.et/api/storefront/v1/payment/
                    yagoutpay/failure       (gateway failure POST)
  Auth            : No user account; the gateway POSTs form-urlencoded
                    fields whose contents are AES-256-CBC encrypted under
                    the merchant encryption key.
  Integrity model : Decryption requires the shared merchant key, then the
                    decrypted me_id, order reference, amount, and currency
                    must all match a PENDING_PAYMENT order placed through
                    YagoutPay before any state changes. Failed validation
                    mutates nothing and 303-redirects to the storefront.
  Current state   : The endpoints are deployed but the gateway feature
                    flag (YAGOUTPAY_ENABLED) is OFF — requests are dropped
                    safely until merchant credentials are configured.
  Merchant key    : To be provided out-of-band via encrypted channel, as
                    with Item 5. Sample encrypted payloads can be
                    generated with the YagoutPay UAT /encryption debug
                    API on request.

--------------------------------------------------------------------------------
  4.5  Auth - Logout / Forgot / Reset / Verify / Resend
--------------------------------------------------------------------------------

  POST /auth/logout
     Body : { "refreshToken": "<REFRESH_TOKEN>" }
     Returns 204 regardless of token validity.

  POST /auth/forgot-password             [rate: 3 / 600 s]
     Body : { "email": "audit-b2c@gedaaistar.et" }
     Always returns 202 (prevents email enumeration).

  POST /auth/reset-password              [rate: 10 / 600 s]
     Body : { "token": "<RESET_TOKEN_FROM_EMAIL>",
              "newPassword": "<STRONG_PW>" }
     Returns 204.  All existing sessions are revoked.

  POST /auth/verify-email
     Body : { "token": "<VERIFY_TOKEN_FROM_EMAIL>" }
     Returns CustomerDto.  Token is single-use and expires after 60 min.

  POST /auth/resend-verification         [rate: 3 / 600 s]
     Body : { "email": "audit-b2c@gedaaistar.et" }
     Always returns 202.

================================================================================
  6. CROSS-CUTTING CONCERNS
================================================================================

  6.1  Standard headers
  --------------------------------------------------------------------------
       Authorization: Bearer <access_token>        (customer + admin)
       X-Guest-Session-Key: <UUID>                 (guest cart only)
       Content-Type: application/json              (all JSON requests)
       X-Correlation-Id: <optional-uuid>           (trace requests)
       X-Requested-With: XMLHttpRequest            (SPA default)

  6.2  Rate limits (per client IP; identified via X-Forwarded-For,
       X-Real-IP, or the Vert.x remote address in that order)
  --------------------------------------------------------------------------
       Storefront /auth/register              5   / 600 s
       Storefront /auth/login                 10  / 60  s
       Storefront /auth/forgot-password       3   / 600 s
       Storefront /auth/reset-password        10  / 600 s
       Storefront /auth/resend-verification   3   / 600 s
       Storefront /auth/me/change-password    5   / 600 s
       Storefront cart mutations              60  / 60  s
       Storefront POST /me/orders             6   / 60  s
       Storefront POST /me/quotes             5   / 300 s
       Storefront GET  /track-order           20  / 60  s

       When exceeded, response is 429 with body
         { "code":"RATE_LIMIT_EXCEEDED", "message":"...",
           "retryAfterSeconds": <n> }
       and header  Retry-After: <n>

  6.3  Error response format (all endpoints)
  --------------------------------------------------------------------------
       {
         "code":    "<UPPER_SNAKE_CASE_CODE>",
         "message": "Human-readable message",
         "details": { "field": ["error-1", "error-2"] }
       }

  6.4  Common HTTP status codes
  --------------------------------------------------------------------------
       200 OK
       201 Created (POST /me/orders, POST /me/quotes, admin POSTs)
       202 Accepted (email flows; never reveals whether address exists)
       204 No Content (logout, delete)
       400 Validation error
       401 Missing / invalid / expired token
       403 Forbidden (role check or business rule)
       404 Resource not found (or masked as such)
       409 Conflict (e.g. duplicate SKU, invalid state transition)
       429 Rate limit exceeded
       500 Internal server error

  6.5  CORS
  --------------------------------------------------------------------------
       Allowed origins  : https://gedaaistar.et and
                          https://admin.gedaaistar.et
       Allowed methods  : GET, POST, PUT, PATCH, DELETE, OPTIONS
       Allowed headers  : Accept, Authorization, Content-Type,
                          Idempotency-Key, X-Requested-With,
                          X-Correlation-Id, X-Guest-Session-Key
       Credentials      : true

  6.6  JWT structure
  --------------------------------------------------------------------------
       Algorithm : HS256
       Claims    :
         sub       - user id (string)
         iss       - configured issuer URL
         aud       - "storefront" or "admin"
         aud_type  - "STOREFRONT" or "ADMIN"
         exp       - expiry (seconds since epoch)
         iat       - issued-at
         jti       - unique jwt id (UUID) - stored server-side for
                     revocation of long-lived tokens
         email     - user email
         roles     - array of role names (admin only:
                     SUPERADMIN, PRODUCT_MANAGER, ORDER_MANAGER,
                     CUSTOMER_MANAGER)
       Admin MFA challenge token uses JOSE header  typ = "mfa-challenge"
       and additional claim  purpose = "mfa-challenge",  TTL 300 s.
